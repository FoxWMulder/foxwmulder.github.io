# Grok  
  
*для тго чтобы нормально отрисовывалось мой компонент мне надо делать НЕ Form1.DoubleBuffered:=True; т.е. оставлять Form1.DoubleBuffered=False; можно ли решить эту проблему?*  
  
**Да, это известная проблема.**  
  
Когда ты используешь **Direct2D** (TCanvas2D / TD2DCanvas) внутри кастомного компонента, свойство DoubleBuffered := True на форме (или на самом компоненте) очень часто ломает корректную отрисовку.  
  
### Почему так происходит?  
  
DoubleBuffered = True заставляет VCL рисовать всё сначала на промежуточный bitmap (GDI), а потом копировать на экран. Direct2D же рисует напрямую через GPU (ID2D1RenderTarget), и эти два механизма плохо дружат — в результате компонент либо мерцает, либо вообще не перерисовывается, либо рисуется криво.  
  
---  
  
### Как можно решить эту проблему?  
  
Вот варианты **по убыванию рекомендуемости**:  
  
### 1. Лучшее решение — отключить DoubleBuffered только для твоего компонента  
  
delphi  
  
```  
constructor TImageListBox.Create(AOwner: TComponent);  
begin  
  inherited;  
  DoubleBuffered := False;        // ← важно!  
  // ...  
end;  
```  
  
И **оставить** у формы DoubleBuffered := True. Это самый правильный подход — форма остаётся плавной, а твой компонент рисуется через Direct2D без конфликтов.  
  
### 2. Принудительно отключать DoubleBuffered при показе компонента  
  
delphi  
  
```  
procedure TImageListBox.CMShowingChanged(var Message: TCMShowingChanged);  
begin  
  inherited;  
  if Showing then  
    DoubleBuffered := False;  
end;  
```  
  
### 3. Отключать DoubleBuffered у родителя (формы) только когда нужно  
  
Можно сделать свойство в компоненте:  
  
delphi  
  
```  
[DisplayName('Force No Double Buffer')]  
property ForceNoDoubleBuffer: Boolean   
  read FForceNoDoubleBuffer   
  write SetForceNoDoubleBuffer   
  default True;  
  
procedure TImageListBox.SetForceNoDoubleBuffer(Value: Boolean);  
begin  
  FForceNoDoubleBuffer := Value;  
  if Assigned(Parent) and (Parent is TWinControl) then  
    Parent.DoubleBuffered := not Value;  
end;  
```

*вот эта строчка "ParentDoubleBuffered:= False;" она у формы отклбючает DoubleBuffered?*  
  
**Ответ коротко и точно:**  
  
**Нет**, строчка ParentDoubleBuffered := False; **не отключает** DoubleBuffered у формы.  
  
### Что она на самом деле делает:  
  
- ParentDoubleBuffered — это флаг, который говорит: **"Брать ли значение DoubleBuffered от родителя (формы) или использовать своё собственное?"**  
- По умолчанию ParentDoubleBuffered = True — компонент **наследует** значение DoubleBuffered от формы.  
- Когда ты ставишь ParentDoubleBuffered := False, то компонент **перестаёт** смотреть на значение формы и использует **своё** свойство DoubleBuffered.  
  
### Правильное использование в твоём случае:  
  
delphi  
  
```  
constructor TImageListBox.Create(AOwner: TComponent);  
begin  
  inherited;  
    
  DoubleBuffered := False;           // своё значение  
  ParentDoubleBuffered := False;     // не брать от формы  
    
  // ... остальной код  
end;  
```  
  
### Итог:  
  
- Форма может спокойно иметь DoubleBuffered := True — она будет работать плавно.  
- Твой компонент будет игнорировать настройку формы и использовать False.  
  
Это как раз **правильный** подход.

**Отличный вопрос!** 👍  
  
### Что такое ControlStyle?  
  
ControlStyle — это **набор флагов** (множество типа TControlStyle), который определяет, **как VCL будет вести себя** с твоим компонентом: как его рисовать, обрабатывать мышь, клавиатуру и т.д.  
  
### Что значит csOpaque?  
  
csOpaque = **"Компонент непрозрачный"** (Opaque).  
  
Когда этот флаг **включён** (стоит по умолчанию у большинства компонентов):  
  
- VCL **автоматически** закрашивает фон компонента цветом Color (или clBtnFace) **перед** вызовом Paint.  
- Это делается для оптимизации.  
  
Когда ты делаешь:  
  
delphi  
  
```  
ControlStyle := ControlStyle - [csOpaque];  
```  
  
ты **убираешь** этот флаг. Это значит:  
  
- VCL **не будет** автоматически закрашивать фон перед Paint.  
- Ты берёшь **полный контроль** над отрисовкой фона сам.  
  
---  
  
### Зачем это нужно в твоём случае (с Direct2D)?  
  
При использовании **Direct2D** это часто **очень важно**, потому что:  
  
- Автоматическая очистка фона VCL (GDI) конфликтует с Direct2D-рендерингом.  
- Может вызывать мерцание, чёрные области или неправильную отрисовку.  
- Убирая csOpaque, ты говоришь системе: «Не трогай фон, я сам всё нарисую».  
  
### Полезные флаги ControlStyle, которые часто используют:  
  
|Флаг|Что делает|Часто используют?|  
|---|---|---|  
|csOpaque|Авто-закрашивание фона|Снимают при Direct2D|  
|csCustomPaint|Говорит, что отрисовка полностью кастомная|Часто добавляют|  
|csDoubleClicks|Включает двойной клик|Обычно оставляют|  
|csCaptureMouse|Захват мыши|По необходимости|  
  
### Рекомендуемый вариант для твоего компонента:  
  
delphi  
  
```  
constructor TImageListBox.Create(AOwner: TComponent);  
begin  
  inherited Create(AOwner);  
    
  DoubleBuffered := False;  
  ParentDoubleBuffered := False;  
    
  // Важные настройки стиля:  
  ControlStyle := ControlStyle - [csOpaque];        // убираем авто-очистку фона  
  ControlStyle := ControlStyle + [csCustomPaint];   // подчёркиваем, что рисуем сами  
end;  
```

### Что происходит в твоём случае:  
  
Когда ты делаешь ControlStyle := ControlStyle + [csOpaque]; — мерцание пропадает. Когда - [csOpaque] — появляется мерцание.  
  
Это значит, что в **твоей конкретной реализации** с Direct2D **лучше оставлять csOpaque включённым**.  
  
### Почему так вышло (объяснение):  
  
- csOpaque заставляет VCL **автоматически** закрашивать фон компонента перед вызовом Paint.  
- В многих случаях с Direct2D это создаёт проблемы (конфликт буферов).  
- Но в твоём случае автоматическая очистка фона VCL, наоборот, **стабилизирует** картинку и убирает мерцание. Скорее всего, в Paint / ReDrawList у тебя не полностью закрашивается вся область каждый раз (есть прозрачные участки, или не всегда вызывается полная перерисовка).

